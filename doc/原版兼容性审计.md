# GSit 3.8.0 与 PumpGsit 的兼容性审计

v0.1.3 包含下文记录的重连坐标、玩法和旧 SQLite 兼容修复。修复验收在提交 `a2a3f16` 上完成。需要对照升级前行为时，可查看同一份记录中的 [v0.1.2 基线](#v012-基线)。

## 主分支修复验证

### 玩家坐着退出并重新加入

原版的 `PlayerQuitEvent` 以 `DISCONNECT` 调用 `stopActions`，普通座位和静态姿势同步执行安全下座。外部传送和死亡各自处理位置。Paper 26.3 在移除载具时还会将玩家 Y 与载具 Y 取较高者。Pumpkin 在触发离开事件前已移除乘客关系，事件完成后写玩家存档。v0.1.2 在离开时丢弃了返回位置，存下的是骑乘位置。修复后，PumpGsit 在此次事件内计算站立位置并完成定位，再清理座位和姿势。[原版退出监听](https://github.com/Gecolay/GSit/blob/04b792026acf95b63f198691d85218a1023e2f92/core/src/main/java/dev/geco/gsit/event/PlayerEventHandler.java#L37-L45) · [原版安全下座](https://github.com/Gecolay/GSit/blob/04b792026acf95b63f198691d85218a1023e2f92/core/src/main/java/dev/geco/gsit/service/SitService.java#L146-L186) · [Pumpkin 保存顺序](https://github.com/Pumpkin-MC/Pumpkin/blob/e318ec5ff87bbd0d72feafe40d6b24f230a8b84a/crates/pumpkin-core/src/lib.rs#L265-L271) · [PumpGsit 实现](../src/gameplay/seat.rs)

复现环境为 Paper Java 26.3 build 249 + GSit 3.8.0 和 Pumpkin `e318ec5f` + Wasm 0.2，默认开启 `center_block`。在完整石地面上从 `(0.2, 150, 0.2)` 右击位于 `(1, 150, 0)` 的下半橡木台阶；另一次直接在原地执行 `/lay`。看到乘客挂载后关闭客户端连接，停服、重启并重新登录，核对首个站立坐标及挂载状态。旧 v0.1.2 在台阶上重登为 `(1.5, 149.925, 0.5)`。

| 动作 | `get_up_return` | Paper 与修复后 Pumpkin 的重登坐标 (X, Y, Z) |
| --- | --- | --- |
| 右键下半台阶 | `false` | `(1.5, 150.525, 0.5)` |
| 右键下半台阶 | `true` | `(0.2, 150.525, 0.2)` |
| 完整方块上 `/lay` | `false` | `(0.5, 150.025, 0.5)` |
| 完整方块上 `/lay` | `true` | `(0.2, 150.025, 0.2)` |
| 从高一格的石块右击同一台阶 | `true` | `(0.2, 151.0, 0.2)` |

两服在这五个用例中的坐标逐项相同，重登时均为站立。在实际 Java 26.3 图形客户端上也复演了默认配置的台阶用例，断开后玩家存档的坐标为 `(1.5, 150.525, 0.5)`。重新加入同一服务器后，原版客户端自然落到台阶顶面，F3 显示 `(1.500, 150.50000, 0.500)`。[实服重连截图](images/slab-reconnect-java26.3.png)

Pumpkin 会在发送离开事件前记录旧载具 UUID，存档可保留 `RootVehicle.Attach`。Wasm 0.2 没有清除此字段的接口；测试中座椅已经移除，重登未重新骑乘，位置也未受该引用影响。服主可将 `get_up_return = true` 配合较高站位再测一遍，确认能回到入座前的高度。[协议回归测试](../tests/support/disconnect.rs)

### 原版 SQLite 往返

原版 Paper 和 Pumpkin 的三个开关默认均为开启。使用明确的原玩家 UUID，库中保留原 UUID 字符串。测试服依次执行以下操作，供服主在副本上复跑。

| 数据所在位置 | 点击坐下、叠坐、爬行 | 核验方式 |
| --- | --- | --- |
| 原版 Paper | 旧玩家 `关、开、关` | 三条原版命令写入，停服保存 `before.db`。 |
| Pumpkin 首次读取 | 旧玩家 `关、开、关` | 用 PumpkinPIE 原名占位符读出三项后分别反转，另将新增玩家三项全关。 |
| Pumpkin 停服重启 | 旧玩家 `开、关、开`，新增玩家 `关、关、关` | 两人均通过三个占位符复核，停服保存最新一致快照。 |
| 将最新库交回 Paper | 旧玩家三项反转为 `关、开、关`，新增玩家反转为 `开、开、开` | 两组不带开关值的命令反馈及三张表的记录，全都符合预期。 |
| 恢复 `before.db` 并重启 Paper | 旧玩家恢复 `关、开、关`，新增玩家回到默认 | 原服再次从备份中的状态反转成功；保留独立的切换后快照。 |

原版未改动的 Java 存储服务和目标 Pumpkin 还对三个默认值的全部八种组合各跑了三次 Pumpkin 启停。每轮核对两个 UUID 的读写、重复行及其删除、其他表与异常行、原版回读和恢复备份。SQLite 完整性检查均为 `ok`。带引号或大小写不同的等价表、缺表、非零 `user_version` 和 `application_id`、附加索引/触发器、仅在 WAL 中已提交的记录均已实测。含未知列的库会拒绝加载；该用例的主文件和 WAL、SHM 逐字节保持原值。[SQLite 往返与变体测试](../tests/support/sqlite.rs) · [部署与回滚](存储.md)

### 同一配置下的玩家操作

- 两名非 OP 玩家在同一方块分别 `/sit`、`/lay`，两人都能保持各自的动作。黑名单中加入 `me` 后，爬行玩家可以执行 `/me`；玩家叠坐时，底座和乘客都收到原版拒绝提示，旁观者收不到被拦下的消息。
- 在默认 `#slabs` 后添加 `oak_slab;0.5`，两服在同一双层橡木台阶生成的座椅 Y 均为 `150.525`。高度和方块状态可同时填写，原版写法和既有 TOML 写法均可使用。
- 原版的 19 份 YAML 语言文件可编辑并热重载。两个实际 Java 26.3 客户端以英语和简体中文执行 `/sit toggle off`，均显示各自语言的原版反馈。中文客户端在右键坐下后显示翻译过的潜行提示，英文旁观者看到实际坐姿。另将配置语言设为德语：荷兰语客户端回退到德语，简中客户端仍显示中文，关闭 `client_language` 后简中客户端也使用德语。故意损坏语言文件后，服内重载保留了上一次可用的消息。
- 实服控制台对同一 UUID 顺序执行 `sit toggle <UUID> OFF`、`… off`、`… nonsense`、`… off extra`，Paper 与 Pumpkin 的例外行数都依次为 **1、2、0、1**。关闭叠坐后，玩家的 `/sit playertoggle` 在两边均回退为普通坐下；再执行 `/sit` 都会起身。26.3 客户端能补全 `/sit tog`、`/crawl tog` 以及 `/sit toggle o`。热重载可立即改变命令行为；静态补全树在服务端重启时更新。实际拒绝偏好子权限后，Paper 对这两个词不返回建议，Pumpkin 玩家仍可看到静态建议。两服执行都只尝试基础姿势，停服核查坐下与爬行偏好表均为零行。[命令与权限](使用与配置.md)
- 双服玩法对照中的 23 项结果逐项相同。其中，普通玩家不能接替别人的同类座位或姿势，拥有踢人权限的 OP 可以接替；干双层、干顶层和含水顶层橡木台阶按规则分别取得座椅高度 `150.275`、`150.775`、`150.525`。

### 旧玩家能否读回偏好

两服都设为离线模式、直连、不经代理。使用同一测试名 `CompatSeat` 和相同的客户端登录 UUID，记录两个服务端实际回给客户端的 UUID。

| 服务端 | 实际登录 UUID |
| --- | --- |
| Paper | `e09e0f14-9f24-3344-93e4-aef19dd4ee78` |
| Pumpkin | `79a1893f-b623-0f64-ff10-122d72829de9` |

1. 在 Paper 保持三项默认值均为开启。玩家依次执行 `/sit toggle`、`/sit playertoggle`、`/crawl toggle`，三个开关均关闭，停服后每张表各有一行 Paper UUID。
2. 原样复制数据库到 PumpGsit，以同一玩家名登录并重复这三条不带参数的命令。每张表都增加了一行 Pumpkin UUID，原有行仍在。这说明该玩家在新服首次读取的是默认开启状态。
3. 重启 Pumpkin 后，再由该玩家执行一次 `/sit toggle`。只有 Pumpkin UUID 的坐下例外被删除，Paper UUID 的三项记录保持原值。
4. 在独立副本的 Pumpkin 控制台以**原 Paper UUID** 执行 `sit toggle e09e0f14-9f24-3344-93e4-aef19dd4ee78 on`，然后停服，把最新库交回 Paper。原玩家再次登录并执行 `/sit toggle`，坐下偏好从开启切至关闭，原 UUID 的行重新出现；叠坐和爬行表内容保持原值。

目标 Pumpkin 在离线直连登录时从玩家名的 SHA-256 取前 16 字节作为 UUID。因此，服主切换前应比较两服**实际登录 UUID**。若不同，三张表本身没有玩家名，不能单靠数据库推断对应关系。保留旧库，在副本上按核实的玩家对应关系迁移，并保留反向映射供回滚使用。本次未实测在线认证或代理转发部署的身份分配。[宿主登录分支](https://github.com/Pumpkin-MC/Pumpkin/blob/e318ec5ff87bbd0d72feafe40d6b24f230a8b84a/crates/pumpkin-core/src/net/java/login/login_start.rs#L62-L66) · [宿主 UUID 算法](https://github.com/Pumpkin-MC/Pumpkin/blob/e318ec5ff87bbd0d72feafe40d6b24f230a8b84a/crates/pumpkin-core/src/net/mod.rs#L74-L76)

### SQLite 读写与拒绝条件

上游三张表都是 `(uuid TEXT)`，记录存在表示反转该配置默认值。对坐下、叠坐、爬行三个默认开关的**全部八种组合**，分别用两个固定 UUID 完成原版 Java 写入、PumpGsit 读取和重复改写、Pumpkin 重启、原版 Java 回读并改写、PumpGsit 再读、恢复备份。各轮的有效偏好均符合预期，`PRAGMA integrity_check` 均返回 `ok`。[原版存储语义](https://github.com/Gecolay/GSit/blob/04b792026acf95b63f198691d85218a1023e2f92/core/src/main/java/dev/geco/gsit/service/ToggleService.java) · [PumpGsit 存储实现](https://github.com/Q2297045667/PumpGsit/blob/v0.1.2/src/storage.rs)

| 测试输入 | 实测结果 |
| --- | --- |
| 重复 UUID 例外 | 两端均只反转一次。原版重复显式写入可以增加重复行；PumpGsit 重复设置同一例外不增加行，恢复默认会删除该 UUID 的所有例外行。 |
| 其他记录 | 插入的 NULL、未知文本、空白、大小写不同的 UUID 文本、BLOB 和无关表在修改目标玩家后均保留。 |
| 仅表名加双引号的等价建表语句 | 如 `CREATE TABLE "gsit_sit_toggle" (uuid TEXT)`。原版能读写，PumpGsit 会报 `unknown GSit schema` 并拒绝加载，因为它会比较建表 SQL 文本。可能影响由其他工具重建过的库。 |
| 缺一张表、非零 `user_version`、偏好表附有触发器 | 原版接受三种测试库，缺表时会补建；PumpGsit 均拒绝加载。 |
| WAL 库 | 原版可读取。PumpGsit 拒绝直接打开；用 SQLite 的只读备份生成独立副本，再把副本切到 `journal_mode=DELETE` 后，已验证可以加载和修改。以上五个拒绝用例的原数据库文件哈希均未改变。 |

适用范围是单进程独占 SQLite、两端停服后交替写入。原版另支持 MySQL，PumpGsit v0.1.2 只实现了 SQLite。备份、WAL 转换、回滚和 SQL 核验命令见[存储指南](存储.md)。

### 命令、语言与外部接口

- 源码逐项对照了原版 7 个主命令及其别名（共 16 个名字）。38 个有 TOML 对应项的配置默认值与原版一致。原版的更新检查、NPC 叠坐、受信任区域限制和非官方功能开关没有对应项。[命令与配置](使用与配置.md)
- 原版 26 个权限节点中有 24 个映射为 `PumpGsit:` 下的对应节点。原版的更新通知和区域绕过节点随对应功能省略；PumpGsit 新增 `PumpGsit:command` 控制共用命令树。[权限映射](使用与配置.md)
- 原版附带 19 份可编辑语言文件，PumpGsit 内置英语和简体中文。启用客户端语言时，原版对缺失语言回退到配置语言；PumpGsit 对非简体中文的客户端回退到英语。[原版语言选择](https://github.com/Gecolay/GSit/blob/04b792026acf95b63f198691d85218a1023e2f92/core/src/main/java/dev/geco/gsit/service/MessageService.java) · [PumpGsit 语言选择](https://github.com/Q2297045667/PumpGsit/blob/v0.1.2/src/lib.rs)
- 六个 `%gsit_*%` 原名保留。对能定位到同一 UUID 的玩家，动作与偏好的布尔含义与原版对应。原版 PlaceholderAPI 接收离线玩家对象；PumpkinPIE 的离线查询可显式传旧 UUID。省略目标且无可解析玩家时，模板保留占位符。使用发布件通过了当时的实服和占位符测试，包括全新安装、旧目录升级、插件热重载、两种 PIE 加载顺序和重启后解析。[占位符说明](占位符.md)

本轮针对 Java 26.3 和选定的 SQLite、PumpkinPIE 组合。原版的领地插件联动、Bukkit 事件/API、活塞随动等既有差异详见[部署范围](构建与验证.md)。Bedrock、其他协议版本和异常断电恢复未在本轮验证。
