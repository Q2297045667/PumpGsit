# PumpGsit 占位符

装上 PumpkinPIE 后，支持 PIE 的聊天、侧边栏和全息文字插件可用原名读取 PumpGsit 的状态和偏好。将下列文字写入消费插件支持占位符的模板，并让它在渲染时传入玩家名。普通聊天消息是否调用解析器，取决于聊天插件。

| 占位符 | 返回 `true` 的条件 |
| --- | --- |
| `%gsit_sitting%` | 玩家坐在 PumpGsit 的方块座位上。叠坐和其他载具单独处理。 |
| `%gsit_posing%` | 玩家正在躺下、翘腿、趴下或旋转。 |
| `%gsit_crawling%` | PumpGsit 正在让该玩家爬行。 |
| `%gsit_toggle%` | 该玩家允许右击方块坐下。 |
| `%gsit_playertoggle%` | 该玩家允许右击玩家叠坐。 |
| `%gsit_crawltoggle%` | 该玩家允许通过潜行等已配置手势进入爬行。 |

布尔结果是小写英文 `true` 或 `false`。后三项读取 PumpGsit 的 SQLite 例外和服务器的默认设置。关闭某一手势的全服配置、权限限制和位置条件由 PumpGsit 执行动作时检查。

## 启用占位符

坐姿、爬行和 SQLite 偏好可独立使用。需要解析占位符时，请单独安装兼容所用 Pumpkin 服务端的 PumpkinPIE。PumpGsit 通过版本 0 的 IPC 协议向名为 `PumpkinPIE` 的提供方注册 `gsit` 命名空间。[PumpkinPIE 项目](https://github.com/Rennex07/PumpkinPIE)

本项目的联调使用 Pumpkin 提交 `e318ec5ff87bbd0d72feafe40d6b24f230a8b84a`，以及匹配该宿主 SDK、关闭自定义文本参数补全的 PumpkinPIE 0.2.6 构建。其他构建请先在目标服务端验证加载和解析。

1. 两个插件加载后，从控制台运行 `pie expansions`。结果应包含 `%gsit%  from PumpGsit: crawling, crawltoggle, playertoggle, posing, sitting, toggle`。提供方较晚加载或重新加载时，PumpGsit 最迟约 30 秒会重新注册。
2. 让有 `PumpkinPIE:use` 权限的玩家站在平地执行 `/pie parse sit=%gsit_sitting% crawl=%gsit_crawling%`。站立时应显示 `sit=false crawl=false`，执行 `/sit` 后再次查询应显示 `sit=true crawl=false`。

## 在线玩家与离线 UUID

玩家命令和模板优先用表中的原名。PIE 会把在线玩家传给 PumpGsit。控制台没有玩家视角，此时原名会保留在文字中，PIE 在 `unresolved` 中列出对应条目。若消费插件需要查询指定身份，可在名称后追加一个冒号和该玩家的完整 UUID。参数明确指定时优先于查看者。

```text
pie parse 坐席=%gsit_sitting:11111111-1111-4111-8111-111111111111% 点击=%gsit_toggle:11111111-1111-4111-8111-111111111111%
```

对离线 UUID，三个动作状态均返回 `false`。三个偏好按原库或相应默认值返回。非法 UUID、缺失的查看者及未知占位符保留原文字。只传离线玩家名时，PIE 找不到在线玩家，无法向 PumpGsit 提供身份。切换服务器前请核对在线验证或代理转发设置，确保同一玩家继续使用同一个 UUID。

开发消费插件时，可向名为 `PumpkinPIE` 的插件发送协议版本 0 的 UTF-8 JSON。以下示例解析玩家 `Steve` 的模板。测试环境中只向 PIE 发消息；PumpGsit 只接受 PIE 发来的注册回调。注册模式为 `never`，每次解析均读取当前状态。[上游 IPC 消息与字段](https://github.com/Rennex07/PumpkinPIE/blob/cc3f05035346326ae27e6675003856bdb6ed7bbe/docs/protocol.md)

```json
{"op":"set_placeholders","viewer":"Steve","text":"座位=%gsit_sitting% 偏好=%gsit_toggle%"}
```

## 更名前的验证记录

2026-11-19，独立消费组件向真实 PIE 发送 `set_placeholders`。在两名 Java 26.3 玩家在线时，分别观察到四种姿态进入和退出时 `posing` 变化，方块坐下时 `sitting` 变化，爬行时 `crawling` 变化。切换方块坐下和玩家叠坐偏好后，只有对应玩家的目标值改变。另一个 Java 26.3 客户端直接输入上述 `/pie parse` 命令，先后看到 `sit=false crawl=false` 和 `sit=true crawl=false`。`/crawl toggle off` 和 `on` 后，`%gsit_crawltoggle%` 分别显示 `false`、`true`。

原版 SQLite 样本的第一位玩家离线时，按上表顺序从提供方得到 `false false false false true false`。在 Pumpkin 控制台为其开启点击坐下后得到 `false false false true true false`。重新启动后仍是后者。无查看者时六个原名均进入 `unresolved`，错误身份保留原文字。[原库结构和回滚](存储.md)

独立服分别按 GSit → PIE 和 PIE → GSit 的顺序加载并正常保存退出。运行中卸载、重载 PIE 后六项恢复解析。连续两次卸载和重载 GSit 时，缺席期间保留原文字，加载后恢复既有偏好。维护者可在 PumpGsit 项目目录中以当前组件复跑。测试使用独立临时目录和回环端口。

```sh
python3 tests/pie_smoke.py --server /path/to/pumpkin \
  --component /path/to/PumpGsit.wasm --pie /path/to/compatible-provider.wasm
```
