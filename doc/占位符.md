# PumpkinPIE 占位符

装上 PumpkinPIE 后，支持 PIE 的聊天、侧边栏和全息文字插件可用原名读取 pumpgsit 的状态和偏好。将下列文字写入消费插件支持占位符的模板，并让它在渲染时传入玩家名。普通聊天消息是否调用解析器，取决于聊天插件。

| 占位符 | 返回 `true` 的条件 |
| --- | --- |
| `%gsit_sitting%` | 玩家坐在 pumpgsit 的方块座位上。叠坐和其他载具单独处理。 |
| `%gsit_posing%` | 玩家正在躺下、翘腿、趴下或旋转。 |
| `%gsit_crawling%` | pumpgsit 正在让该玩家爬行。 |
| `%gsit_toggle%` | 该玩家允许右击方块坐下。 |
| `%gsit_playertoggle%` | 该玩家允许右击玩家叠坐。 |
| `%gsit_crawltoggle%` | 该玩家允许通过潜行等已配置手势进入爬行。 |

布尔结果是小写英文 `true` 或 `false`。后三项读取 pumpgsit 的 SQLite 例外和服务器的默认设置。关闭某一手势的全服配置、权限限制和位置条件由 pumpgsit 执行动作时检查。

## 安装提供方

测试环境使用 Pumpkin 提交 `e318ec5ff87bbd0d72feafe40d6b24f230a8b84a`、Rust 1.100.0 和 PumpkinPIE 0.2.6 提交 `cc3f05035346326ae27e6675003856bdb6ed7bbe`。pumpgsit 使用 Wasm API 0.2，PIE 使用同一宿主保留的 Wasm API 0.1，两者通过 IPC 互通。为匹配该服务端，选配构建使用其 Rust SDK，并关闭 PIE 的自定义文本参数补全。上游的这个补全会在目标宿主的模拟线程发生运行时错误。命令字面参数、`/pie parse`、`/pie expansions` 和占位符解析均保留。[对应 PIE 源码](https://github.com/Rennex07/PumpkinPIE/tree/cc3f05035346326ae27e6675003856bdb6ed7bbe) · [构建补丁](compat/pumpkinpie-0.2.6.patch)

1. 把兼容构建的 `pumpkin_pie_plugin.wasm` 与 `pumpgsit.wasm` 放入服务端的 `plugins/`。此次实测的 PIE 文件 SHA-256 为 `3e4d60653c2638d6053fd4c395c1a9ea348adee1f14e5e92f530ab10a7d0de6c`。PIE 的元数据名必须为 `PumpkinPIE`。它无需文件权限。如果宿主默认要求签名，在 `[plugins.overrides.PumpkinPIE]` 中设置 `allow_unsigned = true` 以加载这个本地组件。仍按 pumpgsit 的安装说明授予 pumpgsit 自己的数据目录读写权限。[下载已验证的 PIE](../dist/pumpkin_pie_plugin.wasm)
2. 启动后检查日志中的 `Loaded PumpkinPIE (0.2.6)` 和 `Loaded pumpgsit (0.1.0)`。控制台输入 `pie expansions`，应出现 `%gsit%  from pumpgsit: crawling, crawltoggle, playertoggle, posing, sitting, toggle`。pumpgsit 会自动发现较晚加载或重新加载的 PIE，最迟约 30 秒重新注册。
3. 让有 `PumpkinPIE:use` 权限的玩家站在平地执行 `/pie parse sit=%gsit_sitting% crawl=%gsit_crawling%`。站立应显示 `sit=false crawl=false`。执行 `/sit` 后重试，应显示 `sit=true crawl=false`。默认二级及以上管理员可运行 PIE 的检查命令。模板的查询由消费插件发起。

交付包中附有已适配的完整提供方源码。解压后，将所列提交的 `Pumpkin` 源码放在 `PumpkinPIE` 同级目录，运行下面最后两条 Rust 命令即可。也可从上游干净副本开始，执行全部命令并将补丁参数改为本机的绝对路径。[下载本次构建对应的 PIE 源码](../dist/pumpkinpie-0.2.6-source.tar.gz)

```sh
git clone https://github.com/Pumpkin-MC/Pumpkin.git Pumpkin
git -C Pumpkin checkout e318ec5ff87bbd0d72feafe40d6b24f230a8b84a
git clone https://github.com/Rennex07/PumpkinPIE.git PumpkinPIE
git -C PumpkinPIE checkout cc3f05035346326ae27e6675003856bdb6ed7bbe
git -C PumpkinPIE apply /path/to/pumpgsit/doc/compat/pumpkinpie-0.2.6.patch
rustup target add --toolchain 1.100.0 wasm32-wasip2
cargo +1.100.0 build --manifest-path PumpkinPIE/Cargo.toml --locked --release \
  -p pumpkin-pie-plugin --target wasm32-wasip2
```

生成的文件位于 `PumpkinPIE/target/wasm32-wasip2/release/pumpkin_pie_plugin.wasm`。两端都不需要 Java 版 PlaceholderAPI。移除 PIE 时，坐姿、动作和玩家偏好仍可独立使用。运行中仅卸载 pumpgsit 时，PIE 的列表可能暂留 `gsit`；这些名称的查询会保留原文字，重载 pumpgsit 后会恢复。完整重启或重载 PIE 可清空这一列表项。

## 在线玩家与离线 UUID

玩家命令和模板优先用表中的原名。PIE 会把在线玩家传给 pumpgsit。控制台没有玩家视角，此时原名会保留在文字中，PIE 在 `unresolved` 中列出对应条目。若消费插件需要查询指定身份，可在名称后追加一个冒号和该玩家的完整 UUID。参数明确指定时优先于查看者。

```text
pie parse 坐席=%gsit_sitting:11111111-1111-4111-8111-111111111111% 点击=%gsit_toggle:11111111-1111-4111-8111-111111111111%
```

对离线 UUID，三个动作状态均返回 `false`。三个偏好按原库或相应默认值返回。非法 UUID、缺失的查看者及未知占位符保留原文字。只传离线玩家名时，PIE 找不到在线玩家，无法向 pumpgsit 提供身份。切换服务器前请核对在线验证或代理转发设置，确保同一玩家继续使用同一个 UUID。

开发消费插件时，可向名为 `PumpkinPIE` 的插件发送协议版本 0 的 UTF-8 JSON。以下示例解析玩家 `Steve` 的模板。测试环境中只向 PIE 发消息；pumpgsit 只接受 PIE 发来的注册回调。注册模式为 `never`，每次解析均读取当前状态。[上游 IPC 消息与字段](https://github.com/Rennex07/PumpkinPIE/blob/cc3f05035346326ae27e6675003856bdb6ed7bbe/docs/protocol.md)

```json
{"op":"set_placeholders","viewer":"Steve","text":"座位=%gsit_sitting% 偏好=%gsit_toggle%"}
```

## 更名前的验证记录

2026-11-19，独立消费组件向真实 PIE 发送 `set_placeholders`。在两名 Java 26.3 玩家在线时，分别观察到四种姿态进入和退出时 `posing` 变化，方块坐下时 `sitting` 变化，爬行时 `crawling` 变化。切换方块坐下和玩家叠坐偏好后，只有对应玩家的目标值改变。另一个 Java 26.3 客户端直接输入上述 `/pie parse` 命令，先后看到 `sit=false crawl=false` 和 `sit=true crawl=false`。`/crawl toggle off` 和 `on` 后，`%gsit_crawltoggle%` 分别显示 `false`、`true`。

原版 SQLite 样本的第一位玩家离线时，按上表顺序从提供方得到 `false false false false true false`。在 Pumpkin 控制台为其开启点击坐下后得到 `false false false true true false`。重新启动后仍是后者。无查看者时六个原名均进入 `unresolved`，错误身份保留原文字。[原库结构和回滚](存储.md)

独立服分别按 GSit → PIE 和 PIE → GSit 的顺序加载并正常保存退出。运行中卸载、重载 PIE 后六项恢复解析。连续两次卸载和重载 GSit 时，缺席期间保留原文字，加载后恢复既有偏好。维护者可在 pumpgsit 项目目录中以当前组件复跑。测试使用独立临时目录和回环端口。

```sh
python3 tests/pie_smoke.py --server /path/to/pumpkin \
  --component /path/to/pumpgsit.wasm --pie /path/to/pumpkin_pie_plugin.wasm
```
