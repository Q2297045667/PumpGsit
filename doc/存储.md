# GSit 3.8.0 玩家偏好迁移与回滚

本插件可直接读写 GSit 3.8.0 的 SQLite 数据文件。Bukkit 端位置为 `plugins/GSit/data/data.db`，Pumpkin 端为 `plugins/data/PumpGsit/data/data.db`。首次全新安装会创建空库。两边可**停服后交替**使用同一份数据。

## Bukkit 数据表和配置

原版 `plugins/GSit/data/data.yml` 只指定后端和连接参数。若 `Database.type` 为 `mysql`，实际玩家数据在 MySQL 的同名三张表中。当前 Wasm 产物提供 SQLite 存储。MySQL 服主应保留原库和原服部署，直连 MySQL、从 MySQL 切换及多服共享写入均未验证。

| SQLite 表 | 操作 | 旧配置默认值 | TOML 中的默认值 |
| --- | --- | --- | --- |
| `gsit_sit_toggle` | 点击方块就座 | `Options.Sit.default-sit-mode` | `sit.default_enabled` |
| `gsit_player_toggle` | 点击其他玩家叠坐 | `Options.PlayerSit.default-sit-mode` | `player_sit.default_enabled` |
| `gsit_crawl_toggle` | 潜行触发爬行 | `Options.Crawl.default-crawl-mode` | `crawl.default_enabled` |

每张表只有 `uuid TEXT` 一列，无主键。存在记录表示反转这一项的服务器默认值。因此两个服务端须分别填写相同的默认值。已有重复记录只会反转一次。v0.1.3 与原版一致，每次显式指定非默认值都会追加一行，恢复默认时会移除该 UUID 的全部同项例外。重复执行安装或切换流程本身不会生成玩家记录。其他 UUID 和原有未知值原样保留。当前座椅和姿势属于会话状态。

## 从 Bukkit 停写、备份、演练和切换

1. 记录旧版 GSit 的版本、三个开关默认值，并让同一测试玩家分别登录两端，核对服务端实际分配的 UUID 和一个已知偏好。本次实测中，即使两端都设置为离线直连，Paper 26.3 和目标 Pumpkin 仍为同名玩家分配不同 UUID。三张偏好表只存 UUID；直接复制数据库会保留旧记录，但新服玩家会读到自己的默认值。遇到这种情况，先保留原库，在副本中用已核实的身份对应关系逐人核对。停掉旧服及该库的其他写入程序；两端的 SQLite 连接使用不同的锁机制，切换和回滚期间应保持单一运行实例。[实服复现与判定](原版兼容性审计.md)
2. 在空的演练目录执行以下命令，以一致性备份建立独立工作副本。将示例路径替换为实际目录，保留备份文件。若旧库有 WAL，SQLite 备份 API 会合并快照中的已提交页。以下命令把演练副本切为回滚日志，也可用于仍运行 v0.1.2 的部署。确认首行输出为 `delete`，完整性结果为 `ok`。

   ```sh
   sqlite3 -readonly /old/plugins/GSit/data/data.db ".backup 'before.db'"
   sqlite3 -readonly before.db ".backup 'staged.db'"
   sqlite3 staged.db 'PRAGMA journal_mode=DELETE; PRAGMA integrity_check;'
   ```

3. 对备份和演练库分别执行以下只读查询，记录行数。第二条查询列出形状异常的 UUID，便于逐条核对。管理员查询离线玩家时使用明确的原 UUID。玩家使用同名账号但 UUID 不同时，应先排查代理转发和在线验证模式。

   ```sql
   SELECT 'sit', count(*), count(DISTINCT uuid) FROM gsit_sit_toggle
   UNION ALL SELECT 'playersit', count(*), count(DISTINCT uuid) FROM gsit_player_toggle
   UNION ALL SELECT 'crawl', count(*), count(DISTINCT uuid) FROM gsit_crawl_toggle;

   WITH prefs(source, row_id, id) AS (
       SELECT 'sit', rowid, uuid FROM gsit_sit_toggle UNION ALL
       SELECT 'playersit', rowid, uuid FROM gsit_player_toggle UNION ALL
       SELECT 'crawl', rowid, uuid FROM gsit_crawl_toggle
   )
   SELECT source, row_id, quote(id) FROM prefs WHERE id IS NULL OR
       length(id) != 36 OR id GLOB '*[^0-9a-f-]*' OR
       length(replace(id, '-', '')) != 32 OR
       substr(id,9,1) != '-' OR substr(id,14,1) != '-' OR
       substr(id,19,1) != '-' OR substr(id,24,1) != '-';
   ```

4. 先在测试用 Pumpkin 的 `plugins/data/PumpGsit/data/` 放入 `staged.db`，文件名改为 `data.db`。填写三个 `default_enabled` 并首次启动。v0.1.3 在同一事务中检查三张偏好表并补齐缺表，保留原有索引、触发器及 SQLite 的版本标记。若发现不兼容的表或对象，会回滚并在日志中指出位置。v0.1.2 的限制见[历史审计](原版兼容性审计.md)。
5. 测试玩家用原 UUID 登录，在空手右击下半台阶之前确认顶部空间足够。核对原偏好，然后执行 `/sit toggle off` 两次，重启并确认点台阶无效。执行 `/sit toggle on` 并重启，再次点击应坐下。记录预期和实际变化。两次命令应只影响该 UUID 在 `gsit_sit_toggle` 的例外。叠坐和爬行分别以 `/sit playertoggle`、`/crawl toggle` 复查。
6. 停止演练服务端，另备份其数据库。以旧服测试副本打开该备份，用同一玩家登录再次核对。演练通过后按同样步骤在正式目录切换。三个 `CREATE TABLE` 在一次事务中执行；偏好修改一次提交一条绑定参数的 SQL。迁移直接复制一致性快照，无需向已有表逐条追加。

## 回滚到 Bukkit

停掉 Pumpkin 后对最新 `plugins/data/PumpGsit/data/data.db` 执行一次 `.backup` 和 `PRAGMA integrity_check`。保留旧服当前库的单独备份，再将这份最新快照交给旧版 GSit，并恢复一致的三个配置默认值。新服期间玩家修改的偏好随快照一并回去。若要明确丢弃切换后的修改，可改用原 `before.db`；先保留切换后快照，便于对照。

## 从旧名 Pumpkin 插件升级

Pumpkin 按插件元数据名选择数据目录和配置段。Linux 上 `plugins/data/pumpgsit/` 与 `plugins/data/PumpGsit/` 通常是两个目录。若旧目录未迁移，新插件会在自己的目录创建默认配置和空库。以下为已安装的版本对应的位置。[宿主数据目录](https://github.com/Pumpkin-MC/Pumpkin/blob/e318ec5ff87bbd0d72feafe40d6b24f230a8b84a/crates/pumpkin-core/src/plugin/api/context.rs#L78-L89) · [宿主配置查找](https://github.com/Pumpkin-MC/Pumpkin/blob/e318ec5ff87bbd0d72feafe40d6b24f230a8b84a/crates/pumpkin-wasm-host/src/runtime.rs#L414)

| 已安装版本 | 数据目录 | `pumpkin.toml` 的插件配置段 | 玩家和权限组节点 |
| --- | --- | --- | --- |
| 原迁移版 `gsit` | `plugins/data/gsit/` | `[plugins.overrides.gsit]` | `gsit:…` |
| v0.1.0、v0.1.1 的 `pumpgsit` | `plugins/data/pumpgsit/` | `[plugins.overrides.pumpgsit]` | `pumpgsit:…` |
| v0.1.2 起的 `PumpGsit` | `plugins/data/PumpGsit/` | `[plugins.overrides.PumpGsit]` | `PumpGsit:…` |

1. 记录当前玩家的一个已知偏好，停服。将旧组件、整份数据目录、`pumpkin.toml` 及玩家和权限组规则备份到服务端目录之外。用上文演练中的 SQLite 备份命令 生成一致快照，运行 `PRAGMA integrity_check` 确认返回 `ok`。
2. 在区分大小写的文件系统上，如果 `plugins/data/PumpGsit/` 尚不存在，将原先使用的整份数据目录改名为 `PumpGsit`。在不区分大小写的文件系统上，若两个名字指向同一目录，可先改成尚未使用的临时名，再改成 `PumpGsit`。如果服务器上已有**两份不同的目录**，先分别备份，核对两个 `config.toml` 的三个默认值、两套数据库按 UUID 的三项偏好，再用确认的数据副本替换目标。两边都有需保留的修改时先在副本中逐人核对后再切换；直接拼接例外表可能改变玩家的有效偏好。
3. 从 `plugins/` 移出旧的 `pumpgsit.wasm` 或 `gsit.wasm`，放入 `PumpGsit.wasm`。按表更新 `pumpkin.toml` 中的配置段，在每个权限组和用户的授权、拒绝及通配符规则中改用 `PumpGsit:`。如果新旧配置段都已存在，先核对并保留原先期望的数据读写与签名策略。[权限映射](使用与配置.md)
4. 启动后检查日志出现 `Loaded PumpGsit`。用旧身份执行 `/gsit help` 和 `/pumpgsit help`，并核对原点击偏好。用 `/sit toggle` 改动后重启，确认新值仍在。再用一个受限玩家和一个管理员分别测试 `/pumpgsitreload`。原聊天模板继续使用 `%gsit_*%`。
5. 如需回滚，停服后将 `plugins/data/PumpGsit/data/data.db` 的最新一致快照和匹配的 TOML 放回表中对应的旧目录，恢复旧组件、宿主配置段和权限规则。保留切换前后的两份备份，便于核对新服期间更改的偏好。

## WAL 和扩展库

v0.1.3 在 WASI 中使用 SQLite 的 `unix-dotfile` 和独占连接。客户端仅在停服后交替访问数据库。保留 WAL 模式时要取得一致快照，或在没有任何进程访问库时将同一时刻的主文件及随附日志一起复制。仅复制仍含未检查点事务的主文件会漏掉已提交的修改。代码保留库的日志模式、非零版本标记、附加表、索引及触发器，并按原结构补建缺失的偏好表。无法判定结构的库及缺主文件而仅剩日志的目录会中止加载。请保存整套文件以便核对。[实服双向读写与两种回滚](原版兼容性审计.md#原版-sqlite-往返)
