# GSit 玩家偏好迁移

PumpGsit 可与 GSit 交替读写同一份 SQLite 或 MySQL 库。默认使用 SQLite。旧服的文件是 `plugins/GSit/data/data.db`，Pumpkin 的文件是 `plugins/data/PumpGsit/data/data.db`。

## 切换前核对

| 偏好表 | Bukkit 配置键 | Pumpkin 配置键 |
| --- | --- | --- |
| `gsit_sit_toggle`（点击坐下） | `Options.Sit.default-sit-mode` | `sit.default_enabled` |
| `gsit_player_toggle`（玩家叠坐） | `Options.PlayerSit.default-sit-mode` | `player_sit.default_enabled` |
| `gsit_crawl_toggle`（潜行爬行） | `Options.Crawl.default-crawl-mode` | `crawl.default_enabled` |

两端的三项出厂默认值均为 `true`。三张表各有一列 `uuid TEXT`，有记录就反转该项默认值。切换时，两端须填写相同的默认值。重复记录只反转一次。显式设为非默认值会追加一行，恢复默认值时移除该 UUID 的全部同项记录。原有未知值会保留。当前座椅和姿势随会话结束。

用一个知道原偏好的玩家，在两端核对服务端分配的 UUID。此前的离线直连测试中，Paper 与 Pumpkin 给同名玩家分配了不同 UUID，复制数据库后新服玩家读到了默认值。遇到这种情况，先核对在线验证和代理转发设置，再用已核实的身份对应关系在副本中检查记录。[在控制台核对 UUID 偏好](使用与配置.md#互动偏好面板)

切换或回滚前暂停旧服和其他写入者。SQLite 两端的文件锁机制不同，应保持单一运行实例。MySQL 也建议交替运行，因为在线玩家偏好有缓存。[构建与往返验证](构建与验证.md#组件验收记录)

## SQLite 备份、演练与切换

1. 在空的演练目录执行下列命令，路径换成旧服实际位置。`.backup` 会带上快照中已经提交的 WAL 修改。第二份副本用于演练，`before.db` 留作回滚。完整性检查应返回 `ok`。

   ```sh
   sqlite3 -readonly /old/plugins/GSit/data/data.db ".backup 'before.db'"
   sqlite3 -readonly before.db ".backup 'staged.db'"
   sqlite3 -readonly staged.db 'PRAGMA integrity_check;'
   ```

2. 在备份和演练库核对三表总行数及不同 UUID 数，再用已知的旧 UUID 检查其记录。可在 `sqlite3 -readonly staged.db` 中执行以下查询。异常值应保留，先核对它对应的来源和身份。

   ```sql
   SELECT 'sit', count(*), count(DISTINCT uuid) FROM gsit_sit_toggle
   UNION ALL SELECT 'playersit', count(*), count(DISTINCT uuid) FROM gsit_player_toggle
   UNION ALL SELECT 'crawl', count(*), count(DISTINCT uuid) FROM gsit_crawl_toggle;

   WITH prefs(source, row_id, id) AS (
       SELECT 'sit', rowid, uuid FROM gsit_sit_toggle UNION ALL
       SELECT 'playersit', rowid, uuid FROM gsit_player_toggle UNION ALL
       SELECT 'crawl', rowid, uuid FROM gsit_crawl_toggle
   )
   SELECT source, row_id, quote(id) FROM prefs WHERE id IS NULL OR
       length(id) != 36 OR id GLOB '*[^0-9a-f-]*' OR
       length(replace(id, '-', '')) != 32 OR
       substr(id,9,1) != '-' OR substr(id,14,1) != '-' OR
       substr(id,19,1) != '-' OR substr(id,24,1) != '-';
   ```

3. 将 `staged.db` 放入测试服的 `plugins/data/PumpGsit/data/` 并命名为 `data.db`。填写相同的三个 `default_enabled`，启动后先核对一位旧玩家的偏好。然后修改偏好、重启并确认改动已保存。例如，点击坐下默认开启时，先执行 `/sit toggle on` 清除旧例外，再执行两次 `/sit toggle off`。空手点击上方有空间的下半台阶应保持站立，表中应有该 UUID 的两行。再执行 `/sit toggle on`，这两行应清除，玩家可再次点击坐下。叠坐和爬行可用 `/sit playertoggle` 和 `/crawl toggle` 核对。
4. 停止测试服，对修改后的库再做一次 `.backup`，在旧服测试副本上读回。演练通过后按同样方式备份和切换正式服。保留 `config.toml` 的 `[database]` 段。出厂配置选择 `type = "sqlite"`，省略 `path` 时用 `data/data.db`。要换文件，可填写相对于插件数据目录的 `path`。

有 WAL 时优先用 `.backup`。如需保存原始文件，在所有访问停止后一起复制主文件和同一时刻的 `-wal`、`-shm` 或 `-journal` 文件。单独复制尚有未检查点事务的主文件会漏掉已提交的修改。PumpGsit 在一个事务中检查三表并补齐缺表，保留原有日志模式、版本标记、索引、触发器和附加表。表结构不兼容，或主文件缺失而日志仍在时，加载会中止并报告位置。[旧表与 WAL 验收](../tests/support/sqlite.rs)

### SQLite 回滚到 Bukkit

停掉 Pumpkin，对最新库运行 `.backup` 和 `PRAGMA integrity_check`。要保留新服期间的修改，就把这份最新快照交给 GSit，并恢复相同的三个默认值。要回到切换前状态，就用 `before.db`。先保存旧服库和切换后快照，再覆盖目标副本。[两种回滚的测试](../tests/support/sqlite.rs)

## MySQL 配置与切换

将下列设置放入 `plugins/data/PumpGsit/config.toml`，已有 `[database]` 时替换整段。首次安装可复制默认配置后修改。旧 `data.yml` 的主机、端口、库名、用户名和密码对应同名字段，端口默认为 3306。原 JDBC URL 的 `args` 应按用途迁移，例如用 `tls` 设置传输方式。切换后端或路径只改变读写目标，SQLite 与 MySQL 之间的数据需另外搬迁。[默认配置](../assets/config.toml)

```toml
[database]
type = "mysql"
host = "db.example.org"
port = 3306
database = "gsit"
user = "gsit"
password = "替换为数据库账户的密码"
tls = "verify_identity"
# 使用私有 CA 时，把 PEM 文件放入插件数据目录，再启用下一行
# ca_file = "mysql-ca.pem"
```

`verify_identity` 是默认值，会校验证书链和所连主机的身份。`tls = "disabled"` 用于明确选择明文，例如隔离测试服的回环连接。配置和备份含有凭据，应限制文件访问权限。

在服务端 `pumpkin.toml` 的 `[plugins.overrides.PumpGsit]` 允许 `fs.read.data`、`fs.write.data` 和 `network.tcp.connect`。连接域名时也允许 `network.dns`，连接远程地址时核对宿主的 `loopback_only` 设置。宿主先检查组件权限，再读取插件配置。无人值守部署应将声明的权限分别列入允许或阻止清单。宿主权限修改后重启 Pumpkin，数据库配置可通过 `/gsitreload` 生效。连接或表结构检查失败时，上一份配置仍生效。[安装和权限示例](../README.md#下载与安装)

1. 原服停写后给库做一致备份，再导入独立的空演练库。以下适用于 InnoDB，备份期间暂停 DDL。库名及客户端登录配置名按实际替换。核对演练库中三表的总行数、不同 UUID 数和测试玩家记录。[MySQL 备份说明](https://dev.mysql.com/doc/refman/8.4/en/mysqldump.html)

   ```sh
   mysqldump --login-path=gsit --single-transaction --no-tablespaces gsit > before-gsit.sql
   mysql --login-path=gsit gsit_rehearsal < before-gsit.sql
   ```

2. 将 Pumpkin 指向演练库并填写相同的默认值。已有三表时，账号需具备 `SELECT`、`INSERT`、`DELETE` 权限。缺少表或数据库时，相应的 `CREATE` 权限可让插件补建。参考 SQLite 演练，读取旧玩家偏好、修改并重启，再用旧端读回。演练通过后切换正式服，保持旧服停写。
3. 要保留切换后的修改，停掉 Pumpkin，备份当前库，把 GSit 的 `data.yml` 指回同一库并恢复相同的默认值。要回到切换前，将 `before-gsit.sql` 导入新的空库，核验后让 GSit 连接该库。[往返测试](../tests/support/mysql.rs)

## 旧库样本与验收

样本都来自 GSit 3.8.0，含两个合成 UUID。SQLite 中 `11111111-1111-4111-8111-111111111111` 在坐下和爬行表各有一行，`22222222-2222-4222-8222-222222222222` 在叠坐表有一行。MySQL 样本从 Paper 26.3 build 256 和 Oracle MySQL 8.4.11 导出，两名玩家按坐下、叠坐、爬行顺序的行数为 `2/0/2` 和 `0/1/0`。[SQLite 样本](../tests/fixtures/gsit-3.8.0.db) · [MySQL 样本](../tests/fixtures/gsit-3.8.0-mysql.sql)

```text
ddc132ebd9356fce92e93d8d53fa54fdfd747b7a55f70d9d9cf7b26c659d86c3  gsit-3.8.0.db
fd80ed9582c7b79fcfeb44d027d8010f55af17b10bcd2bade69ff0058002f158  gsit-3.8.0-mysql.sql
```

SQLite 与 MySQL 实服往返使用 Pumpkin `9b4c00eab` 和 Paper 26.3 build 256 上的 GSit 3.8.0。两端均能读取、修改并重启复读同一份库，切换后新增的偏好可随最新库回旧服，也可恢复切换前的备份。MySQL 另验证了回环明文、私有 CA 校验、首次认证及错误 CA 或密码的配置回退。多服同时修改同一在线玩家的偏好尚未验证。[复跑命令](构建与验证.md#重跑验证)
